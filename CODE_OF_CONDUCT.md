# Bugema Linux Code of Conduct

## Our Commitment

The Bugema Linux project is committed to providing a welcoming, respectful, professional, and collaborative environment for everyone who participates in the project.

Bugema Linux is developed under the **Bugema Open Source Community (BOSC)** at **Bugema University, Uganda**, and brings together students, academic staff, technical staff, researchers, alumni, open-source developers, and other contributors.

We expect all participants to contribute in a constructive and professional manner.

## 1. Expected Behavior

Project participants are expected to:

* Treat others with respect and professionalism.
* Communicate constructively.
* Welcome different technical perspectives.
* Provide useful and respectful feedback.
* Accept constructive criticism.
* Focus discussions on technical and project objectives.
* Give appropriate credit to other contributors.
* Respect project procedures and review processes.
* Protect confidential information.
* Respect intellectual property and software licenses.
* Support new contributors and students.
* Help maintain a safe and productive learning environment.

## 2. Open and Inclusive Collaboration

Bugema Linux welcomes contributors with different levels of experience.

Students and new contributors should be able to ask questions and learn without being ridiculed or discouraged.

Experienced contributors are encouraged to mentor others and help build sustainable technical capacity.

## 3. Unacceptable Behavior

The following behaviors are not acceptable:

* Harassment or intimidation.
* Personal attacks.
* Threats or deliberate attempts to cause harm.
* Discriminatory or degrading conduct.
* Deliberate disruption of project activities.
* Trolling or persistent hostile behavior.
* Publishing private or confidential information without authorization.
* Deliberately introducing malicious code.
* Attempting to compromise project infrastructure.
* Misrepresenting another person's work as one's own.
* Repeatedly ignoring established project procedures.
* Abusing project permissions or access.

## 4. Technical Disagreement

Technical disagreement is normal in open-source development.

Contributors should address disagreements using:

* Evidence
* Documentation
* Testing
* Technical requirements
* Security considerations
* Project objectives
* Maintainability considerations

Disagreement about code or architecture should not become a personal conflict.

Statements should focus on the work rather than attacking individuals.

## 5. Student and Academic Environment

Bugema Linux may be used as a practical project for the **Open Source Systems** course and other academic activities.

Students should be treated as contributors and learners.

Academic status must not be used as a reason to dismiss legitimate technical contributions.

At the same time, students are expected to follow the same project standards relating to:

* Code quality
* Testing
* Security
* Documentation
* Licensing
* Professional conduct

Academic assessment and technical project decisions are separate processes.

## 6. Collaboration with External Contributors

External contributors are welcome to participate in Bugema Linux subject to the project's contribution, security, licensing, and governance requirements.

External contributors should respect the project's institutional context and community standards.

## 7. Reporting Problems

If you experience or observe behavior that violates this Code of Conduct, report it through an appropriate project communication channel.

For technical issues, use the project's GitHub issue and discussion mechanisms where appropriate.

For sensitive matters that should not be publicly disclosed, contact an appropriate project maintainer or designated project authority privately.

Security vulnerabilities should be reported according to the project's security reporting procedure rather than through a public issue.

## 8. Confidentiality

Information submitted privately in relation to a conduct concern should be handled responsibly.

Project administrators and maintainers should avoid unnecessary disclosure of sensitive information.

## 9. Consequences

Behavior that violates this Code of Conduct may result in actions appropriate to the circumstances, including:

* Informal guidance
* Request for corrective action
* Removal of inappropriate content
* Temporary restriction of project participation
* Removal from a project team
* Removal of repository access
* Escalation through appropriate Bugema University procedures where applicable

Actions should be proportionate to the circumstances and consistent with applicable project and institutional procedures.

## 10. Good-Faith Participation

The Code of Conduct should not be used to suppress legitimate technical disagreement, good-faith criticism, or evidence-based discussion.

Contributors should be able to question technical decisions respectfully.

The purpose of this document is to protect constructive collaboration, not to prevent disagreement.

## 11. Scope

This Code of Conduct applies to project participation through:

* GitHub repositories
* GitHub Issues
* GitHub Discussions
* Pull Requests
* Project meetings
* Project communication channels
* Bugema Linux development activities
* Other project-related interactions

## 12. Maintenance

This Code of Conduct may be reviewed and updated as the Bugema Linux community grows.

Changes should follow the project's governance process.
